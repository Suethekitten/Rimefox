# 从旧版升级（DualTrans → 凛狐）

> 本文对应 README 里原来的「从旧版升级」一节。日常升级（0.4.8 及以后）只需要看 [README 的安装步骤](../README.md#安装)。

0.16.0 起阅读器书库存储有升级：旧书会在首次打开阅读器时自动迁移，不需要重新导入；升级前建议先关闭所有阅读器标签页再重载扩展。

## 配置与书库的恢复边界（0.16.4）

| 对象 | 支持的升级输入 | 验证与恢复 |
|---|---|---|
| 配置 | 0.4.8–0.16.3 的已知配置结构（schema 1–9） | 迁移器覆盖历史扁平、engineConfig、providerConfig；schema 1–9 合成快照回归。不是逐个旧安装包的实机保证 |
| 设备密钥 | 配置中的旧 Key、0.15–0.16.3 的 local 凭据 | 迁入扩展源 IndexedDB；会话 Key 不落入设备凭据库；升级不擅自更改用户的保存选择 |
| 阅读器书库 | 阅读器 v1–v3 数据库 → v4；0.16.x 保持 v4 | IDB 升级在同一事务内搬移原书与更新记录；失败整体回滚。已有 v3 真实浏览器迁移用例；更早结构仅兼容，不计入完成实机验收 |

升级前关闭其他阅读器标签页，导出设置并保留原 EPUB/PDF 文件。默认导出不含密钥；只在需要迁移凭据时勾选包含 Key，文件应自行妥善保管并删除。配置导出不包含书库、字体或阅读进度，不是整库备份。

迁移按“准备日志 → 写设备凭据候选 → 提交配置修订号 → 完成日志”执行。会话或设备凭据写入失败时不提交新配置，也不清理旧凭据；最后收尾中断时，下次读取以配置修订号决定提交还是放弃候选。失败后保持原目录，关闭其他扩展页面，重载并重试；不要卸载或清除站点数据。

每次配置结构升级保留一份**不含 Key**的升级前快照（`config_migration_backup`），普通保存不覆盖它。设置 → 缓存与迁移 →「恢复升级前设置」可恢复配置，书库不受影响。当前 Key 仅在服务商、协议、地址都匹配时保留；其他槽位清空，需重新填写。恢复前可先导出当前配置；快照不能找回已删除的密钥。

需要回退程序时：关闭阅读器，保留当前导出与原书，将 **0.16.3** 的程序文件覆盖到同一目录，再重载。它能继续读取 v4 书库，但不能读取新版凭据库，需重新配置 Key；旧版本也会重新带回已知密钥/资源保护缺陷，只适合作为临时恢复。**不支持把已升级的 v4 书库原地降级到 0.15 或更早**；如必须使用旧版本，应在独立目录/浏览器配置中导入原书。不要直接降低 IDB 版本号或删除数据库。

未知的未来配置版本、损坏磁盘、手工修改数据库不在自动恢复承诺内。遇到迁移失败时保留原始文件和脱敏错误，记录升级前后版本；不要反复覆盖数据或上传含 Key 的导出。

## 版本分界

0.4.8 起项目更名为「凛狐 Rimefox」，发布包的文件夹名也从 `DualTrans` 变成了 `Rimefox`。

- 上面「安装」里说的「覆盖到同一个文件夹」适用于 **0.4.8 及以后**的版本之间。
- 如果你装的是 **0.4.7 或更早**的 DualTrans，需要按下面的步骤迁移。

## 为什么不能直接覆盖

**未打包扩展的 ID 是按文件夹绝对路径计算的**，路径变了就是另一个扩展，所以：

- 浏览器会把新旧两版当成两个不同的扩展，可以同时存在；
- 旧版的 API Key、设置、缓存在新版里**不会自动继承**，需要重新填一次。

## 升级步骤

1. 打开旧版设置页，记下 API 地址 / Key / 模型名（Key 忘了就去申请它的平台重新复制）；
2. `edge://extensions/`（Chrome 为 `chrome://extensions/`）→ 卸载旧版 DualTrans；
3. 解压新版 `Rimefox-v<版本号>.zip` → 「加载解压缩的扩展」→ 选 `Rimefox` 文件夹；
4. 在新版设置页填回地址与 Key，点「测试连接」。

## 用配置导出 / 导入迁移（0.4.9 起）

设置页「缓存与迁移」里可以把整份配置导出成 JSON（勾选后才包含 API Key），以后跨版本或换电脑时先导出、再导入即可。旧版没有这个功能，首次迁移仍需手动重填一次。

## 为什么本地开发目录仍叫 `edge-bilingual/`

改目录名同样会改变扩展 ID、丢失设置，所以只在对外名称上做了区隔。加载已经解压的扩展时，请保持文件夹路径不变。
