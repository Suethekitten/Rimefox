# 术语表：首选译法与术语说明

## 使用方式

每条术语保留原文、首选译法与分类。点击该行下方的「术语说明」可展开多行编辑区；已有说明的行显示「已填写」。分类折叠、添加、删除和划词收录沿用原有操作，编辑后仍需保存。

说明可写首选译法的含义、适用语境、限制及例外。例如：

```json
{
  "source": "response",
  "target": "治疗反应",
  "category": "医学",
  "note": "在肿瘤治疗研究中优先使用治疗反应；日常回应、问卷答复等语境应按实际含义翻译。"
}
```

- **无说明**：沿用旧词条的固定译法要求。
- **有说明**：把 target 作为首选译法，结合当前句子及已有可靠上下文判断是否适用。说明允许且原意要求时，可选择更准确的表达；不在译文中输出说明或选择过程。
- 说明不是字符串替换规则，也不是高级自定义指令。不能更改目标语言、输出协议、元素数量或其他翻译规则。

说明上限为 500 个 Unicode 字符，支持中英文标点、引号和正常换行。编辑区显示字符计数；超长时保留完整草稿、标记错误并阻止保存/导出，不能静默截断。导入超长说明会报告错误，不应用该文件。换行统一为 LF，首尾空白移除；空说明不写入存储对象。

## 数据和配置兼容

字段为 `{source, target, category?, note?}`。source/target 的既有清洗、去重和匹配规则，以及术语数量和提示词命中上限均不变。分类仍只是界面元数据。

`normalizeGlossary()` 保留完整说明草稿；保存、CSV/JSON 导入与导出入口负责长度校验。正常旧配置不需要迁移或用户操作，不改变配置版本和扩展版本，也不清理 API、术语或缓存。

整份配置 JSON 导出保留说明。导入时，同名词条未提供 note 字段则保留本机原说明；显式提供空字符串则清空。其余条目集合仍遵循原配置导入的替换规则。缺省字段与显式空值通过导入元数据区分，不把临时标记写进配置。

划词气泡一键收录仍可只填写原文和译法。覆盖已有 target 会保留原 category、note 与位置；不需要在划词气泡中新增说明输入框。

## CSV 格式

新导出固定为：

```csv
source,target,category,note
response,治疗反应,医学,"肿瘤研究中优先使用；
日常答复按实际语境翻译。"
```

逗号、双引号和换行沿用标准 CSV 引号转义，双引号在字段内部写成两个双引号；导出带 BOM 便于 Excel 识别中文。

| 输入形式 | 解释 |
|---|---|
| 有表头 | 优先按 source/target/category/note 名称定位；支持列重排及「原文、首选译法、分类、术语说明」等已知表头 |
| 无表头，两列 | source,target |
| 无表头，三列 | source,target,category |
| 无表头，恰好四列 | source,target,category,note |
| 有表头但其他未知列 | 忽略未知列，不把第四列自动认成 note |
| 无表头且超过四列 | 保留前三列的旧用法，其余忽略，不猜测第四列为说明；需要说明时请提供 note 表头 |

旧两列/三列文件更新同名词条时不清空已有说明。显式 note 表头但某行没有提供对应字段时也保留；写出该字段的空单元格（含结尾逗号）则明确清空。CSV 中的空分类沿用原行为，保留同名旧分类。

`parseGlossaryCsvImport()` 返回 entries 和 noteUpdates；普通 `parseGlossaryCsv()` 仍返回清洗后的词条数组。`mergeGlossaryEntries()` 使用导入元数据区分缺省说明和明确清空；数据规范化后仍不存空字段。重复原文保持原有先出现者优先的清洗规则。

## 提示词、安全与费用

`matchGlossary()` 只对实际命中条目传递 note。`glossaryPrompt()` 将固定译法和语境偏好分开；没有任何 note 时，旧提示词保持逐字一致。

有说明的条目作为 JSON 编码的数据段传递，换行/引号和类似角色标签的字符转义；外围系统规则限定说明只能解释语境，不能执行任务、泄露配置、更改目标语言或 JSON 协议。界面把说明写入 textarea.value，不执行其中的 HTML/脚本。API Key 不会因为说明字段进入模型输入。

这是输入边界和提示词约束，不能据此保证任意模型都能抵抗所有恶意措辞或正确理解多义词；原有翻译解析及输出护栏仍然生效。没有为说明增加模型调用或专用引擎。命中说明会增加当前请求的输入 Token；原有可选严格质量模式仍按自身风险检查及预算工作，说明本身不触发额外复核。

用户术语继续优先于内置专业词库；同源内置词仍按既有规则排除。有说明的用户首选译法不适用时，也不要求模型机械套回同源内置译法。

## 缓存

术语指纹加入非空 note；修改它只使实际命中该词条的原文缓存失效。未命中的说明和分类修改不影响缓存。

没有说明或说明为空时，指纹使用原先字节序列，旧词条缓存兼容；不升级全局缓存 schema，也不清缓存。删除说明会恢复该词条的固定译法身份。匹配仍以原文文本决定，说明不会改变命中频率、边界或术语排序。

node tools/e2e-extension.mjs --glossary-only

纯函数、真实后台加假 API、真实无头 Chrome 设置界面分开验证。`test/fixtures/glossary-context-samples.json` 中 response/charge/cell/model 的不同语境及预设译文明确标为 mock，只验证说明传递和既有 JSON 协议。

真实 AI 语境翻译由用户主动运行付费 API 并对照原文验收；不能把提示词包含说明或假模型返回预设译文当作真实模型消歧成功的证据。
