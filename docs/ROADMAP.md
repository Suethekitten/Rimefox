## 1. 定位与原则

凛狐（Rimefox）是一个**自建 API 的浏览器双语对照翻译扩展**：不接第三方免费端点，不收集用户内容，零构建。

排序原则：

1. **先修问题，再加功能** —— 翻译错位、布局破坏、重复、丢格式优先于新入口
2. **不引入构建步骤** —— 保持「改完文件重载即可」
3. **每个改动配回归测试** —— `selftest` + `test/*.test.mjs` 是唯一能离线验证的防线
4. **公开仓库后按 Issue 推进** —— 修 bug 走补丁版，加功能走次版本

## 5. 版本与发布节奏

### 5.1 版本号规则

- 三处同步：`manifest.json`、`content/core.js` 的 `DT.VERSION`、`package.json`
- 修 bug → 末位 +1；加功能 → 中间位 +1 且末位归零
- `0.9.x` 之后是 `0.10.0`、`0.11.0`（不是 1.0.0）；`1.0.0` 只在用户要求时使用
- 纯文档 / 纯重构提交不升版本

### 5.2 发布流程

- 推 main 且改 `manifest.json` → CI 自动：校验版本 → 自检 → 打包 zip → 摘 CHANGELOG → 建 Release
- CHANGELOG 每版 3–6 条、一句话 ≤ 90 字、只写用户感知；细节写 HANDOFF「本版技术记录」
- 发版前跑 `python3 tools/check-release-notes.py <版本号>`
- 推送前人工确认一次（见 AGENTS.md）

## 6. 改代码前的最低要求

1. 动 `content/dom.js` → 跑 `selftest/index.html`（当前 98 条，必须全过）
2. 动 `lib/` / `background.js` / `options/` → 跑 `test/*.test.mjs`（当前 222 条）
3. 新增跳过规则 → 想清楚会不会把可见内容跳过
4. 新增替换规则 → 想清楚会不会破坏布局或替换正文
5. 新增入口 → 复用 `translate` 消息与缓存，不另起请求链路

## 7. 已知限制（公开后需在首页说明）

| 项 | 现状 |
|---|---|
| API Key | 明文存 `chrome.storage.local`（仅扩展可读；可选会话级存储待做） |
| 翻译缓存 | 短文本会写本机磁盘，与是否开启隐私保护无关（PRIVACY.md 已披露） |
| 隐私脱敏 | 只覆盖可可靠识别的类型；姓名/英文名默认不做 |
| 跨设备 | 配置不云同步，需要导出/导入 |
