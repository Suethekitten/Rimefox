## 2. 数据流（排查顺序）

PDF.js 的 `getTextContent()` 提取已有文字层；依据坐标拼行、判栏并合成段落。原始 canvas 独立渲染图片、背景与排版；不是对每个 PDF 都进行 OCR。新 PDF 默认 `pdf-parallel` 双列，已保存的阅读模式继续保留。

### 版式译文预览

`pdf-layout` 是单独可选的“双列版式（预览）”：左侧原页，右侧复制原页位图，只在通过背景检查且译文能放下的段落框覆盖译文。`pdf-text.js` 以 `captureLayout` 保留段落行框，扫描页的 OCR 文本块则带由识别框换算的同格式 `layoutLines`（见 [OCR-INTERFACE §6.2](OCR-INTERFACE.md#62-pdf-阅读器)）；`lib/reader/pdf-layout.js` 投影框并保守判定近似纯色背景：边缘须几乎同色，内部以背景为主，其余须是贴近背景的笔画（半径随字号放大），以免密集中文被误当复杂背景，实心色块与插图仍被拒绝。`reader/pdf-layout.js` 把底色和译文放在同一个覆盖层上（不改画右侧位图），用 `textContent` 定位译文、缩小字号并检查溢出：先在原框缩到原字号 80%，仍放不下时用 `growLayoutRect` 向本栏右缘和下一段之前的同色空白扩展（最多原高 3 倍，不得碰到其他块，扩展区须通过同一底色检查），最后才缩到 8px；工具栏「显示原文 / 显示译文」只隐藏覆盖层。未替换原因计数写在 `.pdf-layout-view` 的 `data-layout-skips`（untranslated / position / background / fit），排查时先看它。页面提示（`layoutNoticeText`）和「查看本页完整译文」放在页标题下、两张页图上方：提示写已替换数、保留原文数及原因（position / background / fit），以及仍在等待翻译的块数（`noTranslate` 的页码、公式不计）；展开后，未进入版式的段落带 `data-layout-skip` 并在段首标出原因。整页还没有译文时提示「本页译文尚未生成」。提示和入口不跟随正文的段间距 / 行高设置（固定行高、无外边距）。

页高在三种状态下必须一致，否则视口上方的页重新渲染会把下面的内容推走（[Issue #18](https://github.com/Suethekitten/Rimefox/issues/18)，0.18.0 向上滚动被扯回）：未渲染的页用 `reader.css` 的两个伪元素按「提示 + 入口两行 + 半宽页图」占位，不再用整页宽乘比例；画布被回收或排队重渲染时 `holdPdfPageHeight` 把当时的高度写成固定 `height`，渲染完成后在同一步里放开并补上文本块与版式层；直接挂在页上的 `.pdf-blocks` 在版式预览里不显示。占位算不准的情况（提示折成两行、首页与其他页比例不同）由 `keepPdfScroll` 兜底：页顶在视口上方的页高度变了多少，就把滚动位置补多少。缩放、换模式、窗口变宽窄时清掉这些固定高度。回归在 `tools/e2e-pdf-reader.mjs`（样本 `layout-scroll.pdf`，像素比 2 让预算只留约 4 页）。右侧副本与原页共用 §10 的画布预算，缩放 / 换书 / 关书释放，调整窗口后重新适配。

文字层按块判断能否覆盖。横排和 90°／270° 侧向文字各自成块，先把文字坐标投影到实际 PDF 视口，再按显示方向绕框中心旋转覆盖层。遮盖范围与背景取样用同一个投影后的外框；旋转框碰到其他块时保留原文，缩字仍放不下时也保留原文。斜排和原生竖排字体保留原样。图片多、正文少的页面不整页跳过：图注、短正文、照片旁的竖排署名和纯色色带上的栏目名照常参与放置，压在照片上的文字因背景检查保留原文，纯数字页码不送翻（合成样本 `reader/pdf-samples/layout-figure.pdf`）。上下 6% 页边带里字号明显小于正文、又远离正文的行仍按页眉页脚删除；这类边带图注若在真实样本里被删，需要在保住期刊页脚过滤的前提下单独调整 `dropMarginLines`。

识别出的印刷版目录条目保留组成该行的定位框，标题送翻，独立章号和页码从原文拼回。带点线的条目沿用目录检测；无点线时需要目录标题，或有对齐页码及连续章号的大写条目。右栏把页码放在条目框右侧，目录跳转继续使用原书中的印刷页码。目录缓存以实际送翻的标题为原文，升级后首次翻译该条目时，之前包含页码的整条缓存不会匹配。

这是阅读预览，不修改 PDF 字节、不导出翻译 PDF，也不保证与原字体一致。纯色判断是启发式，复杂背景可能误判，必须核对原页；表格 / 公式和放不下的段落保留原样，页面上方的「查看本页完整译文」可展开全部译文并标出这些段落。扫描页在 OCR 完成后用识别框尝试覆盖：识别框四周补 0.3 倍框高（OCR 框紧贴墨迹，扫描字边有晕边），起始字号按墨迹高度与字符种类估算；颜色容差放宽到 ±16 应对纸面噪点，但边缘一致性仍须 98%（放宽比例会让框边切过倾斜的字、露出原字残片）。倾斜扫描件的长行两端会出框，此时逐级加大四周边距（最多 1 倍字号，不碰其他块）取第一个边缘干净的框，否则保留原样；根治在连接器侧，见 [ROADMAP 0.17.2](ROADMAP.md#4-近期安排)。覆盖层是纯色，在纸纹明显的扫描底上能看出浅色矩形；贴着表格线、页眉线的块会保留原文。OCR 识别错误也会原样进入译文，须核对原页。`pdf-parallel` 继续提供可选择复制的双列重排译文。

段落切分：`groupParagraphs` 的行距取本页最小一簇行间距（第 20 百分位起 25% 内，占四分之一以上时），否则取中位数；短段落为主的页面段间距多于行内间距，用中位数会把整页并成一段。

导入：`reader.js importFile` → 检测 PDF（扩展名/magic）→ `importPdf`（只存文件与元数据，**不在导入时开 pdf.js 文档**，避免同页两个文档导致渲染异常）→ 书库记录。

打开：`openPdfBook` → `loadPdfDocument()` → 生成页容器（`aspect-ratio` 占位）→ 目录 `doc.toc()` → `renderVisiblePdfPages()`。

渲染：`renderVisiblePdfPages` 只处理可视范围 ±800px → 串行队列 `pdfRenderQueue` → `renderPdfPage`（canvas 基准宽 = `#bookContent` 宽 − padding，渲染倍率 = `max(1.5, dpr) × zoom`，上限 3）→ 文本块面板 → `applyPdfTranslations`。

翻译：`translatePdfPage` → `PdfTranslator.translatePage`（≤16 段 / 3600 字一批）→ 按下列身份读取 reader 缓存 → 写回块下方。

### PDF 译文缓存与任务生命周期（0.14.2 本地修复）

原 0.14.2 修复未单独发布，现纳入 0.15.0；发布状态以 [ROADMAP](ROADMAP.md#4-近期安排) 为准。

- 键为 `pdf-v2|bookId|page:N|块序号|配置身份|原文 FNV`；读取还要核对记录的配置身份与完整 source，避免哈希碰撞误用。原书与进度、EPUB 缓存不迁移。
- 配置身份由 `lib/reader/pdf-cache.js` 统一生成 SHA-256：包含目标语言元数据、风格 / 强度、服务商 / 协议 / 规范化地址 / 模型、术语 / 提示词、专业策略版本 / 选项、隐私选项、温度与思考配置。显示模式、外观与 API Key 不参与；切回原语言或配置可以复用其译文。
- 旧 `pdf|...` 条目缺少完整配置身份，保留但不复用；下次翻译按当前配置重新生成，删除书时照常一并清理。
- 阅读器请求带 `pdfCacheIdentity`；后台取到当前配置后用同一实现核对，不一致则返回 `errorCode: 'config_changed'`，不发送模型请求，避免设置页与阅读器之间的竞态污染缓存。
- 切目标语言或有效翻译配置会作废旧任务、撤去旧译文并回到有效的原文模式；仅修改配置 / 下拉框不翻译。外观变化保留当前译文。页面监听可信扩展页的 storage 变化，并在明确翻译前重拉去 Key 的配置。
- `PdfTranslator.epoch` 与阅读器文档代际共同检查缓存读取、模型响应和视图写回；关闭 / 换书 / 停止后旧任务不能覆盖当前视图或修改新进度。停止保留已完成的译文，并禁止滚动自动续发，直到明确重新翻译。
- 长块全部切片成功后才写入整块缓存；缺片不把部分译文当成完整结果保存。

## 3. 已知限制（当前）

1. **印刷版目录页码是书内页码**，和 PDF 物理页有前目录偏移；点击可能差几页。没有做页偏移映射。
2. **极少数页仍可能被 pdf.js 编码成单个 text item**：坐标上没有断点，自动拆栏只剩提示，不静默切坏。2026-11-02 复核本地 OBP 样本时发现，第 20 页实际是 4 栏页面（标题横跨多栏），旧逻辑被跨栏标题干扰后回退到「按中线分左右」，导致整页碎成大量小块；现已改为按行首 x 聚类识别栏，4 栏顺序正常。真正单 item 的页面本地样本未复现。
3. **扫描件 0 文本**：按 §5 的系统预览流程处理；未授权、缺组件或语言时提示对应操作，不能识别时仍保留原页。
4. **跨栏/跨页段落按页分块**：段落会在页边界断开，译文也按页。
5. **高倍缩放需要横向滚动页面**：不自动换行/重排。
6. 阅读器画布本身不可选中文字；下方文本块可选中、可翻译。
7. **已有文本流式视图**：可调整字号与行高，在原版与流式间同步到附近页；图表、合并单元格、跨页段落与公式不能完整重建。

另：源 PDF 缺字形时画布显示「口口」，这是文件本身的问题（本地 PDF 软件同样显示），不是渲染 bug；文本提取仍然是正确字符。

## 4. 未来更新候选（未排期）

按收益/成本排序，供接手者决定：

1. **跨页/跨栏段落合并**：把上一页末尾与下一页开头按「无句末标点 + 续行」拼成同一翻译单元，减少断句。
2. **单 text item 的双栏兜底**：已改为按行首 x 聚类识别栏，跨栏标题不会再干扰；真正「整页 1–2 个 text item」的页面仍无法靠坐标拆，只显示复杂版式提示，不静默切。需要更多样本验证后再考虑文本级兜底。
3. **印刷版目录页偏移映射**：用目录页自身的印刷页码与 PDF 页号估算 offset；或点击时按标题回搜。
4. **列表/表格**：项目符号已分段；编号列表、合并单元格、纯文字表格仍是合并文本。数据表在单栏页会按单元格拆开（见 §6）。
5. **缩放体验**：适应宽度 / 双页模式 / 记住每本书的缩放。
6. **性能**：目前串行渲染；大页面可加缩略图或后台预取（注意后台标签页 rAF 暂停，见 HANDOFF §9 第 21 条）。
7. **完善流式阅读**：基础文本流已实现；图表位置、脚注锚点、表格结构与跨页段落合并仍待改进。
8. **表格 / 公式文本清洗（低风险项已落地，2026-11-02）**：表格仅在单栏页、连续行且数据行带数字时按单元格拆（不重建合并单元格）；公式残渣换 `[公式]` 占位且公式块不送翻；脚注标记与上标编号从正文剥离；目录页不再被当成第二栏。表格结构重建、公式识别与纯文字表格仍留待 OCR / 真流式一起评估。

## 5. OCR 系统预览与后续后端

采用可选安装的本地 Native Messaging 连接器，首阶段只开放 Windows.Media.Ocr / Apple Vision。扩展不包含 OCR 运行库，不因平台名称就认定已就绪；系统能力、组件、权限和识别语言以实际检测为准。扩展协议、状态与逐页流程统一见 [OCR-INTERFACE](OCR-INTERFACE.md)，平台交付层级见 [组件 README](../native/ocr-host/README.md)，安装和未签名限制见 [INSTALL](../native/ocr-host/INSTALL.md)。

零文本页只在阅读范围内按需识别，空白页不一定能产生文字；识别文字和文字层进入同一套文本块、搜索、缓存、送翻流程。取消、换书、关书后的旧结果必须丢弃，文字型 PDF 不触发 OCR。图像与文字送翻的隐私边界以 [PRIVACY](../PRIVACY.md) 为准。

### 5.1 未来保留的能力

- 连接器 / 引擎包保持分层；系统预览不等待 PaddleOCR，也不以购买或申请证书为前置条件。签名与公证是将来正式分发的工作，不能与系统 API 自身是否需要证书混淆。
- 通用协议保留后端能力检测、版本 / 模型身份、状态和取消，当前产品入口只展示 system / off，不提供尚未可用的后端选择。
- 未来 PaddleOCR 引擎包可用 GPU，失败时在可恢复错误下回退 CPU，模型随包就位，不在识别过程中下载远程代码。运行库、真实体积和架构支持须单独验证；当前 Windows 自包含连接器的体积不能沿用“几 MB”的早期目标。
- PaddleOCR 与 Tesseract 可作后续宽松许可证候选和对照；Scribe.js 因 AGPL 不集成。只有真实繁 / 简 / 英质量、延迟、内存与安装代价支持时才选择新默认后端，不把官方语言列表当成质量证据。
- 原生组件维护困难时可评估扩展内 WASM 来源；MV3 的执行代码必须随扩展分发，不可按需执行远程下载代码。此路线不进入当前预览界面。

### 5.2 真实样本验收

质量探针命令和字段见 OCR-INTERFACE §8。至少区分合成夹具与真实扫描，记录使用的实际语言模型、分辨率、耗时、文字和坐标；人工参考 CER 要写明范围及是否忽略空格 / 标点 / 大小写。斜图、多栏、竖排古籍、表格、低清和缺语言模型都可能降低质量，不能用普通横排英文结果推断古籍效果。Windows 系统 API 没有置信度字段，不应虚构。

样本和原始结果放忽略的 `reader/pdf-real/`，不进扩展包；一次性证据见 [本轮验证记录](archive/2026-11-05-system-ocr-preview.md)。历史候选评估保留于 [归档](archive/2026-10-31-ocr-candidates.md)，不作为当前产品放行条件。
## 6. 2026-11-01 烂 PDF 实测

- 样本：DPO（arXiv 2305.18290）、RAFT（2104.00680）、YOLOv4（2004.10934），加上已有的中文双栏期刊与 OBP。
- **RAFT 的 LaTeX base64 垃圾**：文本层混入 `<latexitsha1_base64="…">…</latexit>`，已加过滤（纯 base64 长串也剔除），首块从乱码恢复为 `1. Local Feature CNN`。
- **YOLOv4 长段落**：单栏顺序正确，但一页只有 2 个大块（约 2900 字/块），翻译单元偏大。
- **双栏 / 多栏顺序**：中文期刊已按内容流输出正确顺序；OBP 第 20 页这类 4 栏页改为按行首 x 聚类，跨栏标题不会再把栏粘成一片。真正被 pdf.js 编码成单个 text item 的页面仍只提示，不静默切（§3 第 2 条）。
- **图表**：画布保留图表原样；文本只提取图注 / 表格里的文字，表格结构可能被拍平。
- **字号**：只影响下方文本块（PDF 画布不重排）；实测 18px → 文本块 20.16px。
- **模式切换**：原文 / 双语 / 仅译文不重建页面，滚动位置保持（实测 1200 → 1200）。
- **延迟**：假 API 下点击「双语」到译文渲染约 204ms；进度条在开始翻译时即显示，真实 API 超过 3 秒也有进度提示。
- **文字模式提示条**：顶部细条「当前为纯文字重排，图表/公式请切回原版版面」+ 一键切换按钮（非弹窗）。
- **长块切分**：单块超过 1500 字时按句末标点切开再送翻，避免整段翻译质量崩。
- **原版交互**：新增「适合宽度（100%）」「单栏（190%）」缩放按钮，减少模式来回切换。
- **P0 可用性**：加密/损坏 PDF 明确提示；目录面板加「跳页」与「全文搜索」（最多 50 条）；翻译进度条带「停止」；页面文本块过大或碎块过多时标注「复杂版式，文本顺序可能不准确」。
- **文本清洗（2026-11-02 本地实现，0.16.3 收紧）**：公式残渣换 `[公式]` 且公式块不送翻（十六进制哈希 / DNA 序列除外）；脚注 `[1]` / 上标编号按上下文剥离（区间 `[0, 1]`、下标 `a[0]`、单位 `m²`、指数 `10⁶`、同位素 `¹⁴C` 保留），版面上的上下标转成 Unicode 上 / 下标留在正文；目录页逐条输出、标题与页码成对；数据表在单栏页按单元格拆开，纯文字表与多栏页表格保持原样。标题字号明显大于正文时单独成段。

## 10. 画布资源契约（0.16.4）

`pdf-raster.js` 约束单页 4 Mi 像素、单文档全部画布 16 Mi 像素、单边 8192，超限按比例降采样并显示提示。预算覆盖真实 canvas，而不只是页面/译文缓存；LRU 释放离屏 bitmap，滚回时重绘。预算约对应 64 MiB RGBA，**不代表整个 pdf.js、GPU 或浏览器进程内存上限**。缩放、换书、关闭会取消已启动的 RenderTask，未完成的旧代际任务不得再分配画布；无效尺寸直接拒绝。合成样本包括 `/Rotate 90` 与 15000×15000 的 12 页文档，生成命令为 `node tools/make-pdf-samples.mjs`。

版式模式每页有原版 / 译文两张位图，只为实际可视页绘制；按页面纵横比、显示宽度与窗口高度保守分配每对画布的像素预算，避免超大页预取把当前可见页挤出。原页淘汰时同时释放译文副本与对应布局元数据。双列缩放改变整页网格的实际显示宽度；进入 / 离开版式模式重新分配画布，但复用翻译缓存。
