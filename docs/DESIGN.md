# 设计说明

本文说明 凛狐 Rimefox 的**切分模型、注入策略、生命周期与可靠性设计**，以及每处取舍背后的原因。
改了 `content/dom.js` 之前建议先读这里。

---

## 1. 整体结构

```
content script（3 个 classic script，共享 window.__DT）
    core.js   工具层：文本判断、超长拆分、消息封装（带超时）、toast
    dom.js    ★ 切分 + 注入 + 还原 + 诊断
    main.js   调度：开关、批处理、观察器、快捷键、看门狗

service worker（ESM）
    background.js  消息路由、并发闸门、批处理、缓存、重试
    lib/provider.js  OpenAI 兼容客户端
    lib/cache.js     三层缓存：内存 → storage.session → storage.local（短文本）
    lib/config.js    默认值 + 存储 + 版本迁移
```

内容脚本是 classic script，不能 `import`，所以三个文件按顺序加载、通过 `window.__DT` 共享命名空间。
service worker 用 `type: "module"`，可以正常 import。

**零构建**：没有打包器、没有依赖、没有转译。改完在 `chrome://extensions/`（Edge：`edge://extensions/`）重新加载即可。

## 2. 切分模型

### 2.1 单元的定义

一个"翻译单元"= 一段需要送给模型的文本 + 它所在的元素。

```
walk(el):
  1) 没有子元素            → 单元(el)
  2) 子元素全被跳过        → 只翻父级自己的文字（见 2.3）
  3) 有直接文本（段落）    → 单元(el)
  4) 容器（无直接文本）    → 逐个下钻
```

`directText(el)` 只统计 `el.childNodes` 里的文本节点，不含子元素内容——这是区分"段落"和"容器"的关键。

拼文本（`textOf`）和原地替换（`collectTextNodes`）都会绕开 `NON_TEXT_TAGS`（`script` / `style` / `svg` / `noscript` 等）：
否则脚本源码会被当正文发给模型，链接图标里的 `<svg><title>` 会抢走译文。
注意 SVG / MathML 元素的 `tagName` 是小写，查表一律用 `tagOf(el)` 转大写。

### 2.2 什么时候继续下钻（`shouldDescend`）

- flex / grid 容器 → 下钻（一排并列条目，如导航、卡片横排）
- 存在真正的块级子元素 → 下钻
- 至少 3 个并列子元素 → 下钻（列表、菜单）
- 其余 → 不下钻，整体作为一个单元

**为什么 flex 要特殊处理**：flex 容器会把子元素"块化"（`<span>` 的 computed display 变成 `block`）。
如果照 computed display 判断，一行元信息会被拆成多个 span 级单元，译文就会叠进原文里。

### 2.3 为什么"子级全跳过"时不整体翻译

假设一个容器里的段落都翻译过了（都带 `data-dt-src`），此时若把它当成"叶子单元"整块再翻一次：

- 取文本会把**已注入的译文**也带进去
- 结果同一段内容被翻第二遍，且层层容器叠加 → 出现 2~4 份重复译文

所以这里**不整块翻**，只翻父级自己的文字（`ownText`）：`<br>` 当空格，`<code>` / `<kbd>` 这类行内代码照样拼进句子，
已翻译、隐藏、非正文的子元素只留一个分隔空格。没有自己的文字就直接返回——宁可漏掉极少数边界文本，也不能重复。

## 3. 注入策略

### 3.1 默认：追加到元素内部末尾

译文节点 `span`（块级用 `display:block`）追加到源元素**最后一次子节点之后**。

这样做的好处是译文跟随源元素的盒子、字号、对齐、宽度，不会跑到别的布局上下文里。

### 3.2 例外：原地替换（`injectOnly`）

满足任一条件时，**替换元素的文本节点**（保留图标等子元素），而不是追加：

| 条件 | 原因 |
|---|---|
| 仅译文模式 | 就是要把原文换掉 |
| `position: fixed / sticky / absolute` | 盒子尺寸写死，追加必溢出（昵称、日期、浮层标签） |
| `DT.areaOf(el)` 不是 `content` | 控件 / 导航里的界面文字，追加会撑破按钮或把导航条挤成两排 |

`DT.areaOf(el)` 是"这段文字属于页面哪一层"的唯一判定，站点适配问题只改它。判定顺序（命中即返回）：

1. 在目录里（祖先的 id / class 带 `toc`、`table-of-contents`）→ `content`：条目就是正文小标题，要对照着看
2. 自己是控件（`a` / `button` / `label` / `summary` / `role=button|tab|menuitem|link|…`），或沿**行内包裹链**能找到所属控件，且整个控件的文字 ≤ 80 字 → `control`。
   `<a><svg/><span>Code</span></a>` 的 span 属于链接；`<a class="card"><div><span>标题</span></div></a>` 的 span 不算（中间隔了块级 div）；超过 80 字的整条链接是卡片，按正文处理
3. 位于 `header` / `nav` / `role=navigation|banner|menubar` 内 + 字号 ≤ 20px + 只占一行 → `chrome`
4. 其余 → `content`

"只占一行"：行内元素看 `getClientRects()` 有几个行片段，其它元素看 `getBoundingClientRect()` 的内容高度 ≤ 行高 × 1.9。
**不能**读 `getComputedStyle().height`：行内元素的计算值是 `"auto"`，`parseFloat` 得 NaN，判断直接落空（0.4.8 GitHub 顶栏中英两行堆叠的根因）；`line-height: normal` 同理，要按字号 × 1.2 兜底。

原地替换时，每个文本节点同时记下**原值**和**我们写入的值**：

- 站点之后改了它（SPA 原地更新文字、计数变化）→ `DT.releaseReplaced()` 把元素放回"未翻译"，下一轮按新内容重翻
- 还原时只恢复仍是我们写入值的节点，站点改过的保持站点的新内容
- `MutationObserver` 据此（`DT.isOwnWrite`）忽略我们自己造成的文本变更

> ⚠️ **不要**把"文本短"或"元素是 flex"单独作为替换条件。
> 试过"短文本 + 父级是 flex-row 就替换"，在整页 flex 布局的站点上，
> 标题和正文全被替换，用户看到的是"原文被译文顶掉了"。

### 3.3 `textOf()` 为什么要排除自己的节点

`textOf(el)` 递归时跳过 `[data-dt-target]` 与 `[data-dt-ui]` 子树。
否则增量重扫时会把"原文 + 已注入的译文"当成新文本再翻一次，表现为重复译文。

## 4. 生命周期与动态内容

| 触发源 | 处理 |
|---|---|
| MutationObserver（childList / characterData） | 600ms 防抖后增量补翻（忽略我们自己插的译文 / 提示条和自己改写的文本） |
| 点击（捕获阶段） | 300ms 后补扫（Tab 切换、折叠面板只改 class 的场景） |
| 悬停 / 聚焦到菜单类容器 | 400ms 后补扫（下拉菜单渲染较晚） |
| URL 变化（1s 轮询） | `DT.refreshStale()`：只撤掉源文本变了的元素，再增量补扫 |
| `pageshow`（bfcache 返回） | 复位运行状态，触发补扫 |
| 滚动 / 改窗口大小（捕获阶段，页面内部容器也算） | 待翻队列按新位置重排；懒翻译时 400ms 节流补翻新进入范围的内容 |
| 失败段落退避到点 | 自动补扫一次（见 5.2） |
| 设置变更（后台广播 `dt:configChanged`） | 重新拉配置（不含 API Key），快捷键等即时生效，失败退避清零 |

### 4.1 为什么 URL 变化不整页重翻

早期做法是"清空 + 全量重翻"，结果是点开一个帖子/弹层时整页闪烁。

现在每段译文在注入时记录**源文本签名**（`data-dt-sig` = 长度 + 前 24 字符）：

- 源文本没变 → 不动
- 源文本变了 → 撤掉这段译文与标记，等补扫重翻
- 译文节点被站点重绘删掉 → 清标记，让它重新翻

## 5. 可靠性与并发

### 5.1 并发、顺序与批次

| 层 | 默认值 | 作用 |
|---|---|---|
| 页面侧 worker | `concurrency`（默认 6） | 同时进行中的批次 |
| 后台并发闸门 | `concurrency`（同上） | 真正并发的 HTTP 请求数（所有标签页共享） |
| 批次切分 | 按离屏幕距离分级 | 屏幕内 ≤3 条 / ≤500 字符；一屏以内 ≤1000 字符；更远 8 条 / 2000 字符 |

**顺序**：每取一批都按"离当前屏幕多远"排序（屏幕内 → 下方 → 上方，上方距离加倍）。用户中途滚动，下一批就跟着换。

**为什么屏幕内要小批**：请求是非流式的，要等整批生成完才一起返回。一批 2000 字符时眼前这屏要等半分钟；
拆小后分给多路并发同时翻，几秒就出来。屏幕外仍用大批，省请求数。

**懒翻译（`lazy`，默认开）**：只收屏幕上方 1 屏到下方 2 屏的单元，远处的等滚到附近再翻。
没滚到的内容不花钱，代价是快速往下拖时会先看到原文、页内查找只能找到已翻的部分。

**收集上限**：单轮最多 3000 个**会真正送翻**的单元（`DT.collect(root, accept)`，不送翻的不占名额）。
收满了本轮结束后接着收下一批。

### 5.2 MV3 的现实：service worker 会被回收

空闲约 30 秒后 worker 可能被终止，此时 `chrome.runtime.sendMessage` 的回调**可能永远不触发**。

对策：

- `DT.send()` 内置 90 秒超时，超时抛错而不是挂死
- 看门狗：超过 100 秒没有任何批次返回才复位（看"多久没进展"，不看总时长，长页面不会被误杀）；
  复位用轮次编号 `runId` 作废旧一轮，不留全局"中止"状态，复位后自动重来
- 请求超时按"多久没收到数据"计（DeepSeek 非流式请求生成期间会持续发空行保活），另设 180 秒总上限
- 429 / 5xx / 网络错误自动重试 3 次；模型返回条数不对时对半拆开分别翻，不整批重来
- 失败的段落按段落各自退避：5s → 15s → 45s，第 4 次失败放弃，直到内容变化 / 手动重翻 / 改设置
- 弹窗轮询连续失败 4 次才停止，并明确提示"状态同步失败"

### 5.3 标签页级续翻

后台用 `chrome.storage.session` 按 `tabId` 记录"这个标签页正在翻译"，并带上域名。
内容脚本启动时问一次：命中且域名一致 → 自动继续翻译。刷新、前进、后退都能接上。

## 6. 状态与标记

| 标记 | 位置 | 含义 |
|---|---|---|
| `data-dt-src` | 源元素 | 已翻译 |
| `data-dt-target` | 译文节点 | 是我们注入的（诊断/还原/去重都靠它） |
| `data-dt-sig` | 源元素 | 源文本签名（用于 SPA 校验） |
| `data-dt-replaced` | 源元素 | 是"原地替换"型：不参与签名比对，改由 `releaseReplaced()` 比对写入值（见 3.2） |
| `data-dt-ui` | 扩展自己的 UI | 排除在切分之外 |

`DT.restore()` 会：还原被替换的文本 → 删除注入节点 → 清所有标记 → 归零计数。

## 7. 已知取舍

| 取舍 | 现状 | 原因 |
|---|---|---|
| 行内标签不保留 | 段落里的 `<b>`/`<a>` 在译文里丢失 | 需要占位符 + 模型回填，属于 P0 后续工作 |
| 仅译文下的空白 | 中文比英文短，固定高度容器留白 | 内容长度变了，容器高度是站点写死的，无通用解 |
| 站点规则 | 纯启发式，无站点配置 | 通用算法覆盖 80%，剩余靠后续规则库 |
| 图标 / i18n | 无 | 不影响功能，优先级低于核心体验 |

## 8. 改代码前的检查

1. 改 `content/dom.js` → 先跑 `selftest/index.html`（85 条用例，离线）
2. 新增"跳过规则" → 想清楚会不会把**可见内容**也跳过（弹层、下拉菜单常被 `opacity`/`aria-hidden` 标记）
3. 新增"替换规则" → 想清楚会不会把**正文**也替换
4. 发版 → 同步 `manifest.json` 与 `content/core.js` 的 `DT.VERSION`
