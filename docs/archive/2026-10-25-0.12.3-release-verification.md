## 2. P3：关闭翻译后 inlineReordered 残留

- 现象：关闭翻译后页面已还原、`translated=0`，但 `dt:status` / `dt:diagnose` 仍报 `inlineReordered=1`。
- 根因：计数只在成功重排注入时累加，`DT.restore` 只重置了同组其它计数器；该值记录的是会话历史，不是当前页面状态。模式切换、显式重译、动态 DOM 替换、注入失败回滚后同样可能残留或重复累加。
- 修复：`content/dom.js` 新增 `DT.reorderedCount()`，从仍在生效的 `rendered` 记录实时统计（要求源节点仍连接、渲染仍属于我们）；`content/main.js` 的 `summarize()` 与 `dt:diagnose` 直接使用该值，删除累加写入和已失效的重置。还原、模式切换、重译、站点替换节点、失败回滚后自动归零。
- 边界：不改渲染架构、缓存身份、事件监听、原始节点身份或恢复流程；仅替换诊断值的来源。
- 回归覆盖：
  - `test/content-main.test.mjs`：状态跟随实时统计值，归零不影响 `translated`，再次出现时恢复。
  - `selftest/link-order.js`：重排后为 1，`DT.restore` 后为 0，再次重排为 1，站点替换节点后为 0，`pruneDetached` 后仍为 0（离线自检）。
  - `tools/e2e-link-order.mjs`：关闭后归零、重复开关、切双语为 0、切回仅译文/显式重译为 1、框架替换后归零、失败段不计数。

## 4. 0.12.3 功能复测证据

- **英文维基链接语序重排**：仅译文 `translated=3, renderFailed=0, inlineOrderFailed=0, inlineReordered=1`；链接标签与 href 一一对应，原 A 节点身份、属性与点击监听保留，焦点与选区在重排后可用。
- **关闭 / 重复开关**：关闭后 `translated=0, inlineReordered=0`，原文逐字恢复；再次开启仍为 1 且不新增请求；再次关闭归零。
- **模式切换与缓存**：切双语、切回仅译文、显式重译均为 0 新请求；双语 `inlineReordered=0`（双语不移动原链接），切回仅译文与重译恢复为 1。
- **动态 DOM 替换**：站点替换源段后，新段落可继续翻译，旧重排计数与失败计数一并清除，`inlineReordered=0`。
- **阿拉伯语密集链接**：仅译文明确安全失败（`unsupported-inline-order: nonmonotonic-atom-order`，`translated=2, renderFailed=1, inlineOrderFailed=1, inlineReordered=0`），原文完整保留并给出可切双语提示；双语按模型语序正确显示。
- **安全边界**：嵌套包装层链接、引用交错、跨行等结构继续安全失败，不出现部分写入或错误重排（离线专项覆盖）。
