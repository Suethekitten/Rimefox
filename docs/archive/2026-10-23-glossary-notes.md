## 实现

词条支持可选 `note`。source、target、category 含义不变，空说明不写入最终存储对象；原去重、数量上限、匹配边界及排序保留。

说明允许多行和中文标点，上限为 500 个 Unicode 字符。编辑时显示计数，超长说明保留完整草稿并阻止保存/导出；CSV/JSON 导入超长说明会明确报错，整个文件不应用。规范化仅处理 CRLF/LF 和首尾空白，不静默截断。长度检查位于输入/保存边界，纯规范化函数仍能保留超长草稿以便用户纠正。

设置页保留紧凑的原文、首选译法和分类；每行另有可展开的术语说明，多行 textarea 占整行，不增加狭窄表格列。已有说明显示低干扰标识，分类折叠和中英文界面保留。宽屏与 520px 窄屏均已检查实际几何与截图。

真实浏览器测试还暴露了原编辑器的浅拷贝问题：保存基线和正在编辑的术语对象共享引用，编辑说明后保存按钮可能不启用。已将表单读取改为复制每个词条，确保未保存编辑与已保存快照独立。

划词气泡无需增加字段，一键收录仍可只提供 source/target。确认覆盖 target 会保留原 category/note，不改变原位置。

## 提示词和优先级

- 无说明：固定译法提示词保持原先字节内容，不突然放松旧词条要求。
- 有说明：以首选译法和语境说明构成单独的数据段，只在语义适用时优先采用；说明允许且上下文明显不适用时可用其他准确表达。
- 不在网页译文中输出说明或选择过程，不强行建立字符串替换。
- 数据使用 JSON 编码，转义换行、引号及类似角色标签的字符；外围规则明确禁止说明更改目标语言、JSON 协议、条数、其他翻译规则或授权工具/额外请求。
- 仍只发送当前批次命中词条，note 不进入未命中请求。说明本身不触发第二次模型请求，也不建立新引擎；只增加当前命中请求的输入 Token。
- 医学模式的用户术语优先级、提示预算与同源内置词排除保持原机制；用户说明不适用时也不强迫套回同源内置译法。

API Key 不因说明字段进入模型输入。上述结构约束不等于证明任意真实模型都能正确消歧或抵抗所有恶意措辞；翻译解析和输出护栏继续工作。

## 缓存与数据兼容

`matchGlossary()` 将 note 传到提示词，指纹只加入非空说明。修改说明只使实际命中该词条的原文缓存失效；未命中词条不受影响。category 仍不进入指纹。

无说明或空说明的旧词条保持旧指纹算法的输入字节。测试使用从修改前 HEAD 得到的冻结指纹验证兼容；不升级全局缓存 schema，也不清缓存。说明删除后恢复固定译法身份。

旧配置不需用户操作。JSON 导出保留 note；导入同名词条时，缺少 note 字段保留本机原说明，显式空字符串清空。部分设置合并仍保留术语，API、自定义提供商和缓存不被迁移或错误保存清空。导入关于缺省/清空的临时元数据不写入配置。

## CSV 约定

新导出为 `source,target,category,note`，兼容两列和三列。逗号、双引号和换行使用已有 CSV 转义，导出保持 BOM。

优先按已知表头识别列，可重排；未知列忽略，不能仅因处于第四列就当作说明。没有表头时约定两列为原文/译法、三列增加分类、恰好四列增加说明；超过四列仍取前三列并忽略未知扩展，需要说明时应显式提供 note 表头。

旧两列/三列更新不会清空原说明。表头含 note 但某行没有对应单元格时也保留；显式提供空单元格才清空。JSON 导入使用相同的缺省与清空语义。重复原文继续由先出现的有效条目优先。

## 已确认限制与人工验收

真实付费 API 未运行，应由用户主动执行。建议固定服务商、模型和目标语言，分别比较相同术语不填说明与填写说明的结果，核对首选含义和例外语境，同时确认说明本身没有进入译文。模型输出是否符合说明仍取决于模型能力与上下文，不能用提示词拼装或 mock 结果替代人工核对。

旧无表头四列文件没有机器可识别的列名，只能按本文约定解释为 source,target,category,note；若第四列有其他历史含义，应补上真实表头使其作为未知列忽略。无表头超过四列不猜测说明列。

本次没有给普通模式额外增加整页文档上下文采集，仍使用当前翻译管线已有的上下文；没有为多义词另外发请求。原有可选严格医学质量复核仍遵守自身风险规则与预算。
