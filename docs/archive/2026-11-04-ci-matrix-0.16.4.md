# 0.16.4 Checks 矩阵修复（只改测试与 CI）

> 已归档：一次性验证记录。当前检查命令见 [HANDOFF.md](../../HANDOFF.md) §7。

0.16.4 发布后，Checks 运行 [41949177428](https://github.com/Suethekitten/Rimefox/actions/runs/41949177428) 有 7 个任务失败。Release 是独立任务，已正常发布；本次不改运行时代码、不改版本号、不重新打标签或替换安装包。

## 根因与修复

| 失败任务 | 根因 | 修复 |
|---|---|---|
| macOS / Windows 的 Chrome、Edge（4 项） | 运行器开启了减少动画，悬浮入口按设计设为 `transition:none`，自检却无条件要求 left/top 过渡 | `selftest/test.js` 按 `prefers-reduced-motion` 分别断言；新 `tools/check-selftest.mjs` 用 CDP 在 `no-preference` 和 `reduce` 下各跑一遍完整自检 |
| Windows unit | `check-release-notes.py` 输出中文时，Windows 管道的旧代码页抛 `UnicodeEncodeError`，Node 单测没跑 | `tools/checks.mjs` 用 `python -X utf8` 并设 `PYTHONIOENCODING=utf-8` |
| Ubuntu Edge | 密钥 E2E 写死中文文案（「接口地址已更改」「所有更改已保存」）；网络与文案合在一个断言里 | 就绪条件改为语言无关；F9 拆成「零请求」和「当前语言提示」两条，输出请求数、路径、是否带认证头（不输出 Key）；`RIMEFOX_TEST_UI_LANG=zh/en`，CI 的 Chrome 用 zh、Edge 用 en |
| translation | 弹窗的空下拉框在初始 HTML 里本就未禁用，趣味风格测试在配置读取前就判定就绪 | 等新文档、`catgirl` 选项、控件可用且状态不是「检测中」；用新建标签页的准确 tabId；补「切换风格不新增请求」断言 |

原 Edge 运行没有打印请求数，无法事后断定那次是否发出了请求；本地英文界面复现时新地址请求数为 0。

## 本地验证（macOS，Chrome 156，Node 24）

- `PYTHONIOENCODING=cp1252 node tools/checks.mjs unit`：全部通过
- `RIMEFOX_TEST_UI_LANG=zh node tools/checks.mjs browser` 与 `=en`：自检两种动画模式全部通过，密钥 / EPUB / PDF 阅读器 E2E 全部通过
- `node tools/e2e-extension.mjs`、`e2e-inline-layout.mjs`、`e2e-link-order.mjs`：全部通过
- 配置读取延迟 1500 ms 的临时扩展副本：趣味风格专项通过（旧等待条件稳定失败）

本机没有 Edge；Windows / Linux / Edge 以推送后的 Checks 结果为准。
