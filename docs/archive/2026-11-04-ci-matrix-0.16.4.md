# 0.16.4 Checks 矩阵修复（只改测试与 CI）

> 已归档：一次性验证记录。当前检查命令见 [HANDOFF.md](../../HANDOFF.md) §7。

0.16.4 发布后，Checks 运行 [41949177428](https://github.com/Suethekitten/Rimefox/actions/runs/41949177428) 有 7 个任务失败。Release 是独立任务，已正常发布；本次不改运行时代码、不改版本号、不重新打标签或替换安装包。

## 根因与修复

| 失败任务 | 根因 | 修复 |
|---|---|---|
| macOS / Windows 的 Chrome、Edge（4 项） | 运行器开启了减少动画，悬浮入口按设计设为 `transition:none`，自检却无条件要求 left/top 过渡 | `selftest/test.js` 按 `prefers-reduced-motion` 分别断言；新 `tools/check-selftest.mjs` 用 CDP 在 `no-preference` 和 `reduce` 下各跑一遍完整自检 |
| Windows unit | `check-release-notes.py` 输出中文时，Windows 管道的旧代码页抛 `UnicodeEncodeError`，Node 单测没跑 | `tools/checks.mjs` 用 `python -X utf8` 并设 `PYTHONIOENCODING=utf-8` |
| Ubuntu Edge | 密钥 E2E 写死中文文案（「接口地址已更改」「所有更改已保存」）；网络与文案合在一个断言里 | 就绪条件改为语言无关；F9 拆成「零请求」和「当前语言提示」两条，输出请求数、路径、是否带认证头（不输出 Key）；`RIMEFOX_TEST_UI_LANG=zh/en`，CI 的 Chrome 用 zh、Edge 用 en |
| translation | 弹窗的空下拉框在初始 HTML 里本就未禁用，趣味风格测试在配置读取前就判定就绪 | 等新文档、`catgirl` 选项、控件可用且状态不是「检测中」；用新建标签页的准确 tabId；补「切换风格不新增请求」断言 |

## 第二轮：Windows Chrome 阅读器 E2E

第一次推送（`18fb80c`）后 11 个任务中 10 个通过，`browser (windows-2025, chrome)` 在 `e2e-reader.mjs` 的「QA E2：尺寸伪造 EPUB 被拒绝」失败（`status` 为空、无书卡）。原因同样是就绪条件过早：`#bookGrid` 是静态 HTML，而 `boot()` 要等阅读器设置、字体、配置和翻译器加载完才绑定导入控件；慢的运行器上 `change` 事件先于监听器触发，导入根本没开始。测试改为等新文档上 `renderLibrary()` 填好书库（`.empty-library` / `.book-card`，与 `e2e-pdf-reader.mjs` 一致）。在 `boot()` 绑定前额外延迟 2.5 s 的临时副本上，旧测试稳定复现同一失败，新测试全部通过。

## 第三轮：两个偶发失败

`4d625e3` 上 Windows Chrome 已通过，但前一轮通过的两个任务各失败一次：

- translation：「CSV：明确的空说明可清空」。测试的 `saveNote` 只看配置里的说明是否等于期望值；上一步「两列 CSV」只改了首选译法，说明本来就相等，所以点完保存立刻返回，下一次导入落在保存还没结束的窗口里，随后保存完成时用已保存配置覆盖了表单，导入被丢掉（失败时表单显示「所有更改已保存」、保存按钮禁用）。`saveNote` 改为同时等保存栏回到未修改状态；导入后先等保存按钮可用（改动计数是 `setTimeout(0)` 防抖）。`--glossary-only` 连跑：修改前 6 次失败 2 次，修改后 10 次全过。
- Ubuntu Edge：`check-selftest.mjs` 首次冷启动 Edge，20 s 内没写出 `DevToolsActivePort`。改为等 60 s、浏览器提前退出立即报错、保留 stderr 末尾、换新配置目录重试一次，并加上 `--disable-background-networking` / `--disable-component-update`。

## 第四轮：首次安装写配置的竞态

`4d03977` 上浏览器矩阵全部通过，translation 又失败一次：假接口 0 次请求，文章页几乎全部失败。原因：首次安装时 `onInstalled` → `getConfig()` 发现还没有 `_storageRevision`，会写入一份默认配置；E2E 在 service worker 出现后立即直接写入假接口配置，如果扩展的首次写入晚于测试写入，假接口配置就被默认值覆盖（没有 Key、服务商回到默认）。在 `current()` 首次写入前暂停 3 s 的临时副本上稳定复现（当前服务商变成 deepseek、提示没有 Key）。E2E 改为先等首次写入完成，再写夹具，并确认夹具经扩展迁移后仍在；同一副本上修改后全部通过。阅读器两个 E2E 都在页面启动（已走过 `getConfig()`）之后才写配置，不受影响。

原 Edge 运行没有打印请求数，无法事后断定那次是否发出了请求；本地英文界面复现时新地址请求数为 0。
