真实可选权限对话框的确认 / 拒绝仍未人工验收：自动测试验证用户点击申请的路由、拒绝状态，并在独立授权夹具中验证真实 Native Messaging，不伪造用户浏览器授权。Windows 干净机器、浏览器下载标记 / SmartScreen、企业策略、Windows 10 / ARM64、未打包 API 的完整兼容范围未验收。当前本机语言为 en-US、ja、zh-Hans-CN，未安装繁体模型；真实扫描质量见上述实施记录。

Mac 远端 CI 将编译通用产物，并分别在 Apple Silicon / Intel 运行真实 Vision、安装器和双浏览器联调；即使成功，也不能当作下载隔离、Gatekeeper、最低系统和普通 Mac 实机安装验收。没有对应验收资产时保持 Mac 下载禁用；实机步骤唯一维护于 [Mac 验收清单](../../native/ocr-host/README.md#mac-必须补的实机验收)。

本次用户已明确授权推送及 Release 附件上传。Release 工作流等待同提交 Checks / OCR 检查全部成功后才创建草稿；草稿扩展资产须与最终源码一致，体验包使用该真实扩展资产重组，附件全部上传校验后才公开。不覆盖已有同名资产，不强制推送，不跳过失败检查。

## 首轮远端检查发现的问题

推送 `2482a13` 后，两个 Mac 架构均在 Swift 类型推断阶段失败；已将混合字典内的坐标计算拆成显式 `[Double]` 和 `[String: Any]`，计算与协议保持一致。Windows 安装测试的字符串前缀断言不能处理 PowerShell 展开的 8.3 临时路径，改为对真实存在的文件与安装目录各自 canonicalize 后检查相对路径，仍拒绝目录外的可执行文件。这些失败使 Release 门禁拒绝创建草稿；修复必须重新通过完整检查，不以本地静态检查替代 Mac 编译。

Linux 完整翻译 E2E 暴露欢迎页异步初始语言保存与测试夹具的竞态，中文按钮 / 缓存文案断言因界面变英文失败；测试现先等待真实欢迎页 `data-ready` 并关闭，再明确指定夹具语言。窄屏检查等待响应式布局帧稳定，并增加英文同等不溢出断言，不放宽翻译、缓存或布局判定。

新增英文窄屏断言在本地完整 E2E 也失败；加入长标签页标题后，精确复现为诊断按钮延伸到视口外（scrollWidth 596、视口 520），不是术语说明本身。窄屏诊断按钮组及选择器现允许收缩，保留按钮宽度；测试加入长标题夹具，不只调整断言来通过。

第二轮 `464df78` 的 Mac 编译通过，后续 `lipo` 检查因参数顺序错误失败；已将输入文件放在 `-verify_arch` 之前，同步构建、打包、CI 和命令文档。Windows 日志证实 `RUNNER~1` 被展开为 `runneradmin`，普通 Node realpath 未展开短名，断言改用 `realpathSync.native` 获取内核规范路径。上述问题仍须远端实际复跑，不报告为已经通过。

同时核对 [Apple 工具手册](https://github.com/apple-oss-distributions/cctools/blob/main/man/otool-classic.1)，`otool` 默认仅显示宿主架构；双 slice 最低系统检查显式指定 `-arch all`，避免将单 slice 输出误判为通用程序缺失架构。
